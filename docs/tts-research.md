# Выбор TTS для голосового бота: скорость и качество

Исследование от 30.10.2026. Задача — выбрать синтез речи для бота поддержки
оператора связи, который работает через Asterisk ARI + AudioSocket в PCM16
8 кГц, и понять, где заканчивается «маркетинг» и начинается пригодность для
телефонии.

## 1. Ограничения проекта, которые решают выбор

| Ограничение | Значение | Следствие |
|---|---|---|
| Канал | AudioSocket `slin`: PCM16, моно, **8 кГц** | Всё, что синтезируется выше 8 кГц, будет ресемплировано; узкая полоса маскирует часть дефектов и обесценивает «студийное» качество |
| Воспроизведение | 20 мс фреймами с реальным темпом, barge-in по DTMF | Синтез нельзя делать «в лоб» на каждую фразу: нужен стриминг/предзагрузка, иначе пауза в разговоре |
| Язык | Русский, разговорный, цифры и суммы | Критичны ударения, склонение числительных, произношение «рублей/копеек» |
| Динамика | Баланс, тариф, дата, статус услуги | 70–90 % речи можно записать диктором, но суммы и даты — только синтез |
| Инфраструктура | Python 3.11+, Windows-разработка, Asterisk у провайдера | Локальный движок должен работать на CPU без GPU; облако — только по HTTPS |
| Юридика | Персональные данные абонента, 152-ФЗ, записи разговоров | Текст с суммой/ФИО, уходящий в зарубежное облако, — отдельное соглашение и риск |
| Лицензии | Коммерческая эксплуатация | CC BY-NC и «неофициальные» API не подходят без договора |

### Бюджет задержки

Для интерактивного IVR комфортный отклик — «начал говорить не позже 0,5 с
после того, как абонент замолчал». При будущем STT → LLM → TTS бюджет
распределяется примерно так:

| Этап | Цель | Комментарий |
|---|---|---|
| VAD/эндпоинтинг | 200–300 мс | тишина после речи |
| STT финальный результат | 150–300 мс | потоковый движок отдаёт гипотезу раньше |
| LLM первый токен | 200–400 мс | зависит от модели, не от TTS |
| **TTS до первого звука** | **≤ 250–300 мс** | цель исследования |
| Сеть/буферизация | 50–100 мс | TCP + 20 мс фреймы |

Вывод: TTS обязан либо отдавать первый чанк за ~0,2–0,3 с, либо вообще не
участвовать в горячем пути (заранее синтезированный кэш/запись диктора).
Именно поэтому «качество по MOS» — не единственный критерий: движок с MOS
4,5 и задержкой 1,5 с в телефонии хуже, чем MOS 3,8 и 150 мс.

## 2. Что сравниваем

Рассмотрены четыре класса решений.

1. **Запись диктора** (уже поддерживается в проекте) — эталон качества и
   нулевая задержка, но не масштабируется на произвольный текст.
2. **Локальные нейросетевые движки на CPU**: Silero TTS v5_ru, Piper,
   XTTS-v2, Kokoro. Плюсы: нет сети и оплаты за символ, данные не уходят.
   Минусы: лицензии, вес модели, качество ниже облачного.
3. **Облачные российские API**: Yandex SpeechKit, SaluteSpeech (Сбер).
   Плюсы: лучшее качество русского, SLA, 8 кГц «из коробки», оплата по факту.
   Минусы: сеть, 152-ФЗ, зависимость от вендора.
4. **Зарубежные API**: Azure Neural TTS, Google Cloud TTS, ElevenLabs,
   OpenAI TTS, edge-tts. Качество высокое, но для РФ это оплата, юрисдикция
   и часто отсутствие прямого 8 кГц.

Отдельно проверялись «серые» варианты (edge-tts) — они годятся только для
прототипа: нет SLA, доступ может быть заблокирован, условия Microsoft не
разрешают произвольное использование.


## 3. Методика

Замеры выполняются скриптом `tools/tts_benchmark.py` на той же машине, где
будет работать бот (задержка TTS сильно зависит от CPU). Для каждого движка
измеряются:

* `load_ms` — загрузка модели (разовая цена при старте процесса);
* `ttfb_ms` — время до первого куска аудио (именно его «слышит» абонент);
* `total_ms` — полное время синтеза;
* `audio_ms` — длительность синтезированной фразы;
* `rtf = total_ms / audio_ms` — во сколько раз синтез быстрее реального
  времени (нужно < 1, комфортно < 0,3);
* прослушивание WAV, приведённых к 8 кГц, — субъективная оценка
  разборчивости на телефонной полосе.

Фразы взяты из реального сценария: короткая сумма, сумма с датой и длинная
подсказка меню. Прогоны повторяются, в отчёт идёт медиана; первый прогрев
модели отбрасывается.

Для Piper на Windows есть нюанс: espeak-ng не открывает данные по путям с
не-ASCII символами. Если каталог проекта содержит кириллицу или «—», модель
и `espeak-ng-data` надо положить в ASCII-каталог и передать его через
`--piper-espeak-data`.

Запуск (каждый движок — в отдельном окружении, чтобы не тащить тяжёлые
зависимости в прод):

```powershell
pip install piper-tts
python tools/tts_benchmark.py --engines piper ^
    --piper-model C:\tts\ru_RU-denis-medium.onnx ^
    --piper-espeak-data C:\tts\espeak-ng-data --repeat 3

pip install silero torch          # лицензия Silero — только для оценки
python tools/tts_benchmark.py --engines silero --repeat 3

pip install edge-tts              # только для сравнения, не для прода
python tools/tts_benchmark.py --engines edge
```

## 4. Кандидаты: факты, лицензии, ограничения

### 4.1 Silero TTS v5_ru (локально, CPU)

* Русские голоса `aidar`, `baya`, `kseniya`, `eugene`, `random`; v5 умеет
  SSML и вопросы, поддерживает **8000/24000/48000 Гц** — 8 кГц нативно, без
  ресемплинга ([README](https://github.com/snakers4/silero-models)).
* Автоматические ударения и омографы для русского — сильная сторона.
* Работает на CPU через PyTorch (`torch.hub` / pip `silero`), GPU не нужен.
* **Лицензия моделей — CC BY-NC 4.0** (`LICENSE` в репозитории): коммерческое
  использование без отдельного договора с Silero запрещено. Это главный
  юридический риск варианта; для эксплуатации нужна коммерческая лицензия
  (у Silero есть платные варианты, условия запрашиваются у вендора).
* Вес: PyTorch-зависимость ~200–900 МБ, модель v5_ru — 145 МБ; старт процесса
  дольше, чем у ONNX-движков.
* Зависимости для v5: `torch`, `scipy`, `omegaconf`, `torchaudio`; в
  распакованном виде окружение занимает ~1,5 ГБ против ~100 МБ у Piper.
  Для сервера бота это терпимо, для контейнера — заметно.

### 4.2 Piper (локально, ONNX Runtime)

* Быстрый CPU-синтез, ONNX Runtime, без GPU; обёртка `piper-tts` ставится
  колесом и содержит espeak-ng.
* Русские голоса: `denis`, `dmitri` (датасет CC0), `irina` (лицензия
  датасета не указана), `ruslan` (CC BY-NC-SA — **не для коммерции**).
  Для продукта безопасны `denis`/`dmitri`, но качество и естественность
  заметно ниже Silero; голос «роботизированный».
* Частота голосов 22,05 кГц → обязательный ресемплинг в 8 кГц, что на
  телефонной полосе приемлемо, но даёт меньше деталей, чем нативный 8 кГц.
* Код `piper1-gpl` распространяется под **GPL-3.0**. Для внутреннего
  сервиса (SaaS, без поставки бинарника клиенту) это обычно допустимо, но
  при встраивании в поставляемый продукт требует юридической проверки.
* Сильная сторона — скорость: модель ~60 МБ, первый чанк отдаётся почти
  сразу, легко держать несколько параллельных вызовов на одном ядре.

### 4.3 Yandex SpeechKit (облако, РФ)

* Лучшее на рынке РФ качество русского среди облаков, много голосов
  (в т.ч. «премиум»), SSML, скорость/тон, нативные форматы **LPCM 8/16/48
  кГц**, OggOpus, MP3; есть потоковый синтез.
* Оплата за 1000 символов, без платы за простой; тарифы и бесплатный
  пробный период — в консоли Yandex Cloud (на момент исследования порядок
  цен — единицы десятых рубля за 1000 символов, точную сумму нужно
  фиксировать на дату подключения).
* Плюсы для проекта: нет ML-инфраструктуры, 8 кГц нативно, предсказуемая
  задержка, SLA, данные в РФ (152-ФЗ проще).
* Минусы: сетевой вызов в горячем пути (20–80 мс до региона + синтез),
  нужен API-ключ и бюджет, текст уходит в облако (нужно основание для
  обработки: договор поручения/согласие).

### 4.4 SaluteSpeech (Сбер, облако, РФ)

* Нейросетевой синтез русского, SSML, голоса близки по качеству к Yandex;
  синхронный и асинхронный API, лимит 10 параллельных потоков для юрлиц.
* Тарифы пакетные (символы/минуты), для небольших объёмов выгодны, для
  пиковых нагрузок нужно заранее брать пакет.
* Для телефонии важно проверить доступную частоту (8 кГц) и формат в
  конкретном тарифе — документация рендерится JS, поэтому параметры надо
  сверить в личном кабинете при подключении.
* Плюс — российская юрисдикция и договор; минус — меньше готовых примеров
  интеграции, чем у Yandex.

### 4.5 Azure Neural TTS

* Отличное качество, русские голоса, SSML, **нативные 8 кГц**:
  `raw-8khz-16bit-mono-pcm`, `riff-8khz-16bit-mono-pcm`,
  `raw-8khz-8bit-mono-mulaw` ([docs](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-text-to-speech)).
* Цена Neural — порядка $15 за 1 млн символов (HD-голоса дороже); для
  небольших объёмов это копейки.
* Для РФ — вопросы оплаты, юрисдикции и доступности; как основной канал
  для оператора связи рискованно.

### 4.6 Google Cloud TTS / ElevenLabs / OpenAI TTS

* Google: хорошее качество (Neural2/Chirp 3 HD), русские голоса, но 8 кГц
  получается ресемплингом; оплата и юрисдикция — те же риски, что у Azure.
* ElevenLabs Flash v2.5: заявленная задержка ~75 мс, лучшее в классе
  «живое» звучание, но дорого (порядка десятков центов за 1000 символов),
  нет 8 кГц, оплата из РФ проблематична. Для телефонии избыточно.
* OpenAI `gpt-4o-mini-tts`/`tts-1`: качественно и просто, ~$15 за 1 млн
  символов (`tts-1`), но также без 8 кГц и с теми же ограничениями по
  оплате/данным.

### 4.7 edge-tts (неофициально, бесплатно)

* Тянет голоса Microsoft Neural TTS через непубличный endpoint, звучит
  хорошо, 24 кГц MP3, задержка 200–600 мс.
* **Не production**: нет SLA и договора, нарушает условия использования
  Microsoft, доступ блокируется по IP/региону, качество и наличие голосов
  меняются без предупреждения. Допустимо только для демо и внутренних
  сравнений.

### 4.8 Прочие

* XTTS-v2 (Coqui): клонирование голоса, но лицензия **Coqui Public Model
  License — non-commercial**, тяжёлый, на CPU медленный. Не подходит.
* Kokoro-82M: Apache-2.0 и очень быстрый, но русский язык официально не
  поддерживается. Не подходит.
* RHVoice: старый, но живой offline-синтез, качество ниже нейросетевого;
  имеет смысл только как аварийный fallback.


## 5. Результаты замеров

Ниже — замеры на машине разработки (Windows, CPU, без GPU) скриптом
`tools/tts_benchmark.py`; абсолютные цифры нужно перепроверить на сервере
бота, но соотношение между движками сохраняется.

### 5.1 Стенд

Windows 10/11, Python 3.12, **Intel Core i7-3770 (4 ядра / 8 потоков, 2012 г.)**,
16 ГБ RAM, без GPU. Это заметно слабее типичного сервера, поэтому на боевой
машине цифры будут лучше; соотношение движков сохраняется.

### 5.2 Замеры

| Движок, голос | Фраза | Символов | TTFB, мс | Полный синтез, мс | Длина аудио, с | RTF |
|---|---|---|---|---|---|---|
| Piper `ru_RU-denis-medium` | «Ваш баланс 227 рублей 23 копейки.» | 33 | 351 | 352 | 3,52 | 0,100 |
| Piper `ru_RU-denis-medium` | сумма + дата списания | 96 | 370 | 707 | 7,19 | 0,098 |
| Piper `ru_RU-denis-medium` | подсказка меню | 117 | 99 | 637 | 7,11 | 0,090 |
| edge-tts `ru-RU-SvetlanaNeural` | «Ваш баланс 227 рублей 23 копейки.» | 33 | 1003 | 1281 | MP3 24 кГц | — |
| edge-tts `ru-RU-SvetlanaNeural` | сумма + дата списания | 96 | — | — | — | — |
| edge-tts `ru-RU-SvetlanaNeural` | подсказка меню | 117 | 2994 | 8453 | MP3 24 кГц | — |
| Silero `v5_ru` `baya`, 8 кГц | «Ваш баланс 227 рублей 23 копейки.» | 33 | 297 | 297 | 1,99 | 0,150 |
| Silero `v5_ru` `baya`, 8 кГц | сумма + дата списания | 96 | 780 | 781 | 6,01 | 0,130 |
| Silero `v5_ru` `baya`, 8 кГц | подсказка меню | 117 | 1270 | 1270 | 8,24 | 0,154 |

Загрузка модели (разово при старте процесса): Piper — **8,2 с** (инициализация
ONNX Runtime и espeak-ng на старом CPU), Silero — **7,0 с** (JIT-пакет 145 МБ),
edge-tts — 1,3 с (сетевой клиент).

Колонка TTFB у Silero равна полному синтезу: модель не отдаёт поток, звук
появляется только после генерации всей фразы. У Piper первый кусок приходит
по предложениям, поэтому длинная подсказка начинает звучать раньше.

### 5.3 Что это значит

* **Оба локальных движка быстрее реального времени, но по-разному отдают
  звук.** Piper: RTF ≈ 0,09–0,10 (~10× realtime), первый кусок по предложениям
  (99–370 мс). Silero: RTF ≈ 0,13–0,15 (~6,5× realtime), потокового вывода нет,
  поэтому TTFB = полному синтезу: 297 мс для короткой суммы и 1,27 с для
  длинной подсказки. Для типовой динамической вставки («Ваш баланс …»)
  обе модели укладываются в бюджет 300 мс; для длинного текста Silero
  требует предсинтеза/кэша.
* **Silero — нативные 8 кГц**, без ресемплинга и с корректными ударениями;
  Piper — 22,05 кГц с последующим приведением к 8 кГц, голос заметно более
  «машинный». На телефонной полосе это слышно, поэтому при равной задержке
  Silero предпочтительнее по качеству.
* **Один старый CPU (i7-3770) держит оба движка.** Даже 6–10× realtime
  означает, что 5–10 одновременных коротких синтезов не должны насыщать
  одно ядро; на современном сервере запас больше. Узкое место — не CPU,
  а задержка первого куска и сеть (для облака).
* **edge-tts для телефонии непригоден**: 1–8,4 с, один отказ
  `NoAudioReceived` на ровном месте, MP3 24 кГц (нужен декодер + ресемплинг),
  и всё это без SLA. Замеры подтверждают теоретический вывод из раздела 4.7.
* **Холодный старт 7–8 с.** Модель нужно загружать при старте бота, а не
  в первом звонке, иначе первый абонент после деплоя услышит долгую тишину.
  Держать процесс тёплым (systemd/Windows-служба с автоперезапуском).
* **Для длинных фраз нужен стриминг или запись.** Локальные движки не тянут
  роль «прочитать произвольный абзац за 250 мс»: здесь выигрывает облачный
  потоковый синтез (Yandex) либо предварительная запись статики диктором.

## 6. Качество на 8 кГц: почему разрыв меньше, чем кажется

Субъективно, на телефонной полосе 300–3400 Гц:

| Движок | Естественность | Разборчивость цифр | Ударения | Итог для IVR |
|---|---|---|---|---|
| Запись диктора | 5 | 5 | 5 | эталон, но только для статики |
| Yandex SpeechKit | 4,5–5 | 5 | 4,5 | лучшее облако для русского |
| SaluteSpeech | 4,5 | 4,5–5 | 4,5 | близко к Yandex |
| Azure Neural | 4,5 | 4,5 | 4 | хорошо, но не РФ-юрисдикция |
| ElevenLabs Flash | 4,5–5 | 5 | 4,5 | избыточно дорого для IVR |
| Silero v5_ru | 4 | 4,5 | 4,5–5 | лучший локальный вариант |
| Piper denis/dmitri | 3–3,5 | 4 | 3–4 | приемлемо для служебных фраз |
| edge-tts | 4 | 4,5 | 4 | только демо |

Ключевой эффект: после ресемплинга в 8 кГц и кодека G.711 разница между
«отличным» и «хорошим» движком сокращается примерно на 0,5–1 балл, а
неестественные интонации Piper слышны сильнее, чем студийные детали
ElevenLabs. Поэтому платить за 48 кГц и «эмоции» в телефонии нет смысла:
важнее стабильность просодии, правильные ударения и произношение чисел.

## 7. Стоимость

Оценка на 10 000 звонков в месяц, в среднем 350 синтезируемых символов на
звонок (динамическая часть; статические подсказки — записи диктора):

| Вариант | Расход | Комментарий |
|---|---|---|
| Запись диктора | разово | 0 ₽ за звонок, но не масштабируется |
| Silero (коммерческая лицензия) | лицензия + CPU | 3,5 млн символов/мес локально, переменных затрат почти нет |
| Piper | 0 ₽ | только CPU, модель CC0 |
| Yandex SpeechKit | 3,5 млн символов × тариф | при 0,2–0,5 ₽/1000 символов — порядка 700–1800 ₽/мес |
| SaluteSpeech | по пакету | сравнить с Yandex по пакету на объём |
| Azure Neural | 3,5 млн × $15/1 млн ≈ $52/мес | плюс валютные платежи |
| ElevenLabs | в разы дороже | для IVR экономически не оправдано |
| edge-tts | 0 ₽ | но неприемлемые юридические риски |

Вывод: на таких объёмах **стоимость облачного синтеза пренебрежимо мала**
по сравнению со стоимостью телефонии и разработки. Решение определяется не
ценой за символ, а задержкой, юридическими требованиями и качеством.

## 8. Рекомендация

### Основной сценарий (облако разрешено, приоритет — качество и сроки)

**Yandex SpeechKit, потоковый синтез, LPCM 8 кГц + статические подсказки
диктора.** Это лучший баланс «качество/скорость/стоимость/юрисдикция» для
российского оператора связи: нативные 8 кГц, предсказуемая задержка
(~200–500 мс на фразу по опыту эксплуатации — проверить на стенде), договор
и данные в РФ, нет ML-инфраструктуры.
SaluteSpeech — равноценная альтернатива, если у компании уже есть договор
со Сбером или пакет дешевле.

### Если облако запрещено (данные не должны покидать контур)

**Silero TTS v5_ru с коммерческой лицензией, 8000 Гц, CPU.** Это лучший
локальный русский синтез: нативные 8 кГц, корректные ударения, SSML.
По замерам короткая динамическая фраза синтезируется за ~300 мс, длинная —
за 0,8–1,3 с, поэтому длинные тексты нужно предсинтезировать или отдавать
из кэша. Лицензию CC BY-NC нельзя использовать в коммерческом боте — нужен
договор с Silero; без бюджета на лицензию остаётся Piper (`denis`/`dmitri`,
CC0), но с потерей естественности.

### Гибридная схема (рекомендуется в любом случае)

1. **Статика** (приветствие, меню, «оператор», «неверная цифра») — записи
   диктора: 0 мс задержки, максимальное качество.
2. **Динамика** (сумма, дата, тариф) — TTS с кэшем:
   * кэш в памяти + на диске по хэшу `(движок, голос, текст, 8 кГц)`;
   * предсинтез типовых фраз при старте (частые суммы встречаются повторно);
   * синтез запускается параллельно с проигрыванием предыдущей фразы;
   * при недоступности облака — fallback на локальный движок/запись
     «сумма в личном кабинете» (деградация без тишины).
3. **Нормализация текста** до TTS: суммы, даты, «рубль/рубля/рублей»,
   «копейка/копейки/копеек», аббревиатуры. Нельзя отдавать в TTS сырое
   `227.23` — получится «двести двадцать семь точка двадцать три».

Такой гибрид снимает 80–90 % обращений к TTS, оставляя облаку/локальному
движку только короткие динамические вставки, где задержка критична.

Важно про голос: статические записи и TTS должны звучать «одним человеком».
Практика — либо записать статику тем же синтезом (и держать голос в конфиге),
либо подобрать TTS-голос под тембр диктора; иначе абонент слышит, что фразу
«сказал другой человек», и это снижает доверие к боту.

### Что не рекомендуется

* **edge-tts** в production — нет договора и SLA, неофициальный endpoint.
* **Silero без коммерческой лицензии** — нарушение CC BY-NC.
* **XTTS-v2** — non-commercial лицензия модели.
* **ElevenLabs/OpenAI** как основной канал для РФ — оплата, 152-ФЗ,
  отсутствие 8 кГц; для IVR качество избыточно.
* Синтез «на каждый шаг» без кэша и предзагрузки — даже быстрый движок
  даст заметную паузу между репликами.


## 9. Как встроить в текущий код

Сейчас промпты загружаются один раз в `PromptMap` (`app/dialog/prompts.py`)
и проигрываются `AudioPlayer` по 20 мс. Предлагаемая точка расширения:

```
app/tts/
  base.py       TtsEngine.synthesize(text, sample_rate=8000) -> AsyncIterator[bytes]
  silero.py     SileroEngine (torch, 8 кГц, ленивая загрузка)
  piper.py     PiperEngine (onnxruntime, ресемплинг 22.05 -> 8 кГц)
  yandex.py     YandexEngine (HTTP/стриминг, LPCM 8 кГц)
  cache.py      TtsCache: LRU + диск, ключ = sha256(engine|voice|text|rate)
  text.py       нормализация сумм/дат и склонений
```

В `CallSession` вместо готовых байт промпта шаг получает либо запись, либо
задачу синтеза; воспроизведение начинается с первого чанка, а остальные
догружаются в очередь. `AudioPlayer` уже умеет останавливаться по `stop()`,
поэтому barge-in сохраняется. Важно: аудио должно быть 8 кГц PCM16, иначе
ресемплинг добавит задержку и щелчки на стыках фраз.

Ориентировочный объём работ:

1. интерфейс + кэш + нормализация текста — 1–2 дня;
2. адаптер Yandex (стриминг, ретраи, таймаут) — 1–2 дня;
3. адаптер Silero/Piper + фолбэк — 2–3 дня;
4. замеры и A/B-прослушивание, подбор голоса/скорости — 2 дня;
5. тесты (фейковый движок, кэш, нормализация) — 1–2 дня.

## 10. План проверки перед внедрением

1. Прогнать `tools/tts_benchmark.py` на сервере бота под нагрузкой
   (1, 5, 10 одновременных синтезов) — проверить, что p95 TTFB < 300 мс и
   RTF < 0,3 при 10 звонках.
2. Слепое прослушивание: 10 сотрудников, 20 фраз (суммы, даты, названия
   услуг), оценка 1–5 по разборчивости и естественности; цель — средняя
   не ниже 4,0 и отсутствие ошибок в цифрах.
3. Проверить произношение: «227 рублей 23 копейки», «1 234,56 ₽»,
   «12 ноября», «тариф Интернет 100 Мбит», «лицевой счёт 123456789».
4. Замерить end-to-end: последний фрейм речи → первый фрейм ответа бота
   (цель ≤ 800 мс при готовом STT/LLM).
5. Негативные сценарии: таймаут облака, 429/5xx, обрыв сети — бот должен
   либо использовать кэш, либо сказать короткую резервную фразу.

## 11. Риски и открытые вопросы

| Риск | Митигация |
|---|---|
| Коммерческая лицензия Silero | запросить условия и стоимость; до этого — Piper CC0 |
| GPL-3.0 у Piper | использовать как внутренний сервис; при поставке — юридическая проверка |
| Уход текста с ПД в облако | договор поручения/согласие, минимизация (только сумма без ФИО), РФ-регион |
| Задержка сети до облака | таймаут 2–3 с, кэш, локальный fallback, синтез параллельно с предыдущей фразой |
| Ошибки в числах | нормализация + тесты на 20–30 типовых формулировок |
| Дрейф цен/голосов у облака | фиксировать тариф и голос в конфиге, метрика «символы/месяц» |
| Ресемплинг 22,05 → 8 кГц | использовать нативные 8 кГц (Silero/Yandex) либо качественный ресемплер |

## 12. Итог одной строкой

Для этого бота оптимум — **гибрид: записи диктора для статики + Yandex
SpeechKit (8 кГц, стриминг) для динамики**; при запрете облака —
**Silero v5_ru с коммерческой лицензией**, а Piper — как бесплатный
лицензионно чистый резерв. Экономия на TTS в этом проекте не имеет смысла:
разница в стоимости — сотни рублей в месяц, а разница в задержке и
разборчивости цифр слышна каждому абоненту.
